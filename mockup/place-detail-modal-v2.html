Place detail — v2 · identity fields folded into the one edit session; no second Save

Design decisions — read before reviewing

  1. One editor, one Save. The prior round's separate "Details" block (its own Edit/Save/Cancel) is gone. Name/Category/City/Location now live inside the SAME edit session as About/My review, and commit through the SAME sticky .modal-foot "Discard draft" / "Save changes". There is exactly one pencil in the header; it opens everything at once. The empty-state "+ Add notes" / "+ Write a review" CTAs still enter this same edit mode (see enterEditMode() in the script).
  2. Read mode drops the raw coordinate. Category and city stay as the existing .tag chips under the title — that was already doing its job. Latitude/longitude is gone from permanent view; instead there's a small "View on map" link (reusing the app's existing .detail-link icon-link pattern, not a new control) — nobody scans a number pair to judge whether a pin is right, they look at the map.
  3. The hierarchy fix: identity fields occupy the header's own footprint, not a new section. In edit mode the title becomes a title-styled input and the two tag chips become two compact selects, in the exact same visual slot the read-mode title/tags sit in. Nothing new is inserted between the header and About — the fields most people will never touch this session (they're here to write a review) don't get a competing bordered "Details" block fighting for attention below the fold.
  4. Location itself is a collapsed disclosure, even inside edit mode. "Location set · Change" opens the exact .coord-input/.coord-status/.coord-ok/.coord-note/.coord-toggle pattern already shipped in Add Place (ported byte-identical from src/index.css) with the current coordinate pre-filled and the reversible GCJ-02 note. Correcting a pin's position is rare compared to fixing a name typo or writing a review, so it stays out of sight until asked for — one more lever against the "too many fields at once" problem the previous round tripped on.
  5. Validation is one shared error, not four. Missing name/category/city, or an unparsable location, all resolve to the one .save-error line already sitting above Save — the same place a failed network save already reports through. No inline per-field error styling was invented.

Round 2 — reviewer findings addressed

  1. Focus management on every mode transition. enterEditMode()/attemptSave()/discardConfirmed()/handleCloseClick() now all move focus explicitly (see applyFocusForTransition()): entering edit or hitting a validation error focuses the name input; save-success, discard-confirmed and "close mid-edit" all land back on the header pencil (#editBtn-{frame}); opening the discard-confirm step focuses "Keep editing". The location-toggle's own re-render got the same treatment. Restores the pattern v1 had and this file had dropped.
  2. Identity fields now lock while saving. .modal[data-mode="saving"] .identity-edit input/select/button gets the same opacity/pointer-events treatment the prose textareas already had — the name input, category/city selects, location toggle and coordinate field can no longer be edited under a live spinner.
  3. Bigger hit areas on "Location set · Change" and "View on map." Both get a real ~40px min-height in place of the old zero-padding text row. The location toggle also picked up darker ink and a heavier weight per the reviewer's note (c) — now reads as an actionable row, not a caption.
  4. "View on map" now actually reuses .detail-link (ported byte-for-byte from place-detail-modal.html) instead of a same-shaped-but-separate class; .modal-map-link is left holding only the header-indent/chevron/hit-area bits that are genuinely new.
  5. The dialog's accessible name no longer depends on an element that goes display:none. A stable .visually-hidden <h2> now carries id="modalName-{frame}" and is always rendered; the rich visual title (icon + name) is aria-hidden so it isn't announced twice.
  6. Discard-confirm copy no longer overclaims. It now reads "…including any changes to name, category, city, location, notes and review" rather than always naming the identity fields regardless of what was actually touched.
